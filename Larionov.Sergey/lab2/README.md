# Лабораторная работа № 2 — вариант 10

Сергей Ларионов. «Волк и семеро козлят», независимые процессы, один хост и несколько клиентов. Вариант включает все три транспорта из задания.

## Структура проекта

- `src/` содержит исходники и заголовки хоста, клиента, протокола и транспортов.
- `tests/` содержит проверки обмена между процессами, тайм-аутов и очистки ресурсов.
- В корне находятся `CMakeLists.txt`, `Makefile`, `build.sh`, `run_tests.sh` и инструкция.
- Собранные программы `host_*` и `client_*` появляются в корне.

## Сборка и запуск

Нужен Linux с glibc 2.30 или новее, компилятором C++17 и Qt Widgets. Команды для Ubuntu 24.04.

```bash
sudo apt install build-essential cmake qt6-base-dev
cd Larionov.Sergey/lab2
make -j4
```

Запустите хост в графической сессии Linux или через WSLg.

```bash
./host_pipe
```

Скопируйте команду с PID из окна хоста. Её можно выполнить одновременно в нескольких терминалах.

```bash
./client_pipe PID_ХОСТА
```

Для других режимов используйте пары `host_fifo` / `client_fifo` и `host_sock` / `client_sock`. `make` вызывает `build.sh`, который собирает в отдельном временном каталоге и удаляет его при выходе. CMake подхватывает исходники и создаёт пару программ для каждого `conn_*.cpp` автоматически. Сборка использует `-Wall -Werror`. Команда `make clean` удаляет шесть исполняемых файлов.

## Проверки

Нужен Python 3. Запуск из каталога `lab2`:

```bash
bash ./run_tests.sh -j4
```

Скрипт собирает проект и проверяет каждый транспорт с шестью одновременно запущенными клиентами, автоматический ход, отклонение подключения с другим транспортом, пятисекундные тайм-ауты при остановке клиента и аварийном завершении хоста, штатное завершение и удаление ресурсов. Qt работает в режиме `offscreen`, поэтому графическая сессия для этих проверок не требуется.

## Правила игры

До подключения первого козлёнка хост ждёт. Для хода введите число от 1 до 100 и нажмите «Сделать ход». Через три секунды без подтверждения хост сам выбирает случайное число. Число участников `n` фиксируется в начале хода, а новые клиенты входят в игру со следующего хода. Каждый живой козлёнок выбирает число от 1 до 100, каждый мёртвый — от 1 до 50. Живой прячется при разнице не больше `70 / n`, а мёртвый воскресает при разнице не больше `20 / n`. Хост возвращает каждому клиенту его статус и показывает числа и итог хода в окне. Два хода подряд, на которых все козлята мертвы, завершают игру и клиентские процессы.

## Как устроено подключение

1. Клиент посылает хосту `SIGUSR1` с кодом транспорта. Хост считывает сигнал через `signalfd`, создаёт отдельный поток и ресурсы сеанса, затем отвечает `SIGUSR1` с идентификатором сеанса. Стандартные сигналы могут сливаться, поэтому клиент повторяет запрос до ответа в пределах пяти секунд. Хост игнорирует повторные запросы уже зарегистрированного PID.
2. Два именованных POSIX-семафора, созданных через `sem_open`, сигнализируют о поступлении сообщений в каждом направлении. После подтверждения подключения хост удаляет имена семафоров. Оба процесса продолжают работать с открытыми семафорами.
3. Во время пауз хост периодически посылает контрольные сообщения. Ожидания сигнала, семафора и операций транспорта ограничены пятью секундами. При потере связи клиент завершает работу, а хост показывает причину и продолжает работу с другими клиентами.

| Режим | Канал передачи сообщений |
| --- | --- |
| `pipe` | Два анонимных канала `pipe2`. Хост передаёт клиенту нужные концы через `SCM_RIGHTS` по служебному Unix-сокету и закрывает этот сокет. |
| `fifo` | Два именованных канала `mkfifo`, по одному на каждое направление. |
| `sock` | Дуплексный потоковый сокет `AF_UNIX`. |

Хост удаляет FIFO, файлы сокетов и каталог сеансов при штатном завершении. `SIGINT` и `SIGTERM` запускают то же завершение, что и закрытие окна. После принудительного `SIGKILL` каталог `/tmp/os-lab2-<UID>-<PID>` может остаться.
